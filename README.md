# MingLi-Bench · LLM 领域推理评测基准

一个针对垂直领域推理任务（命理 / 人格分析）的 **LLM 评测基准**，用于比较多模型在结构化推理任务上的表现，并为线上模型与提示词版本选型提供可复现依据。

> 本项目是 [命理鉴心](https://minglijinxin.com)（商业化 AI 问答产品）的配套评测体系：产品线上每次换模型、换提示词版本，都先用这套基准做横评，再决定上线哪一版。

## 1. 要解决的问题

- 同一套垂直领域结构化推理任务，不同大模型的输出质量差多少？
- 线上该选哪个模型、哪一版提示词？把这件事从"凭感觉"变成"可复现的测量"。
- 输出可比的排名 + 失败模式归类，指导线上默认方案选择。

## 2. 评测集设计

| 设计项 | 内容 |
|---|---|
| 任务形态 | 领域结构化推理：给定输入信息，输出固定字段的推理结果（JSON 协议） |
| 测试集构成 | 固定题集，覆盖典型输入、边界输入、易混淆输入三类 |
| 跨版本可比 | 每轮迭代使用同一批题目，输入文本与输出协议完全一致 |
| 输入控制 | 同一题目在不同模型 / 提示词版本下使用完全相同的输入 |

## 3. 评分口径（权重在评测前固定）

1. **格式合规**：是否合法 JSON、字段是否齐全（硬门槛，不合规直接 0）
2. **字段正确性**：关键字段与领域规则是否一致（历法换算、节气边界、大运起运等）
3. **推理一致性**：同一输入多次请求是否稳定输出同一结论
4. **可解释性**：结论是否有可追溯的依据字段

最终得分为加权分。权重在评测开始前固定，避免"看到结果再调权重"。

## 4. 横评结果（示例）

- 在固定题集上横向比较多个主流大模型，输出可复现排名与分项得分。
- 提示词方案对比：`CARD + SCORES` 方案横评得分 **45%、排名第 3**，随后部署为线上默认方案，旧版本保留为迭代基线。
- 关键发现：**输出格式合规率**是拉开差距的主因，而不是模型规模；字段缺失在长输出中最常见。

## 5. 回归测试与代码审计

- 建立 **5 组回归用例**，覆盖四柱、节气边界、大运起运三类核心计算，对照专业软件（文墨天机）验证。
- 审核 AI 生成代码，依据领域规则识别 **4 处底层数据 / 算法错误**，判定为代码缺陷而非模型理解偏差——这类问题仅凭报错日志无法定位，必须用领域知识反推正确输出。

## 6. 局限

- 单一垂直领域，结论不能直接外推到通用任务。
- 评分含人工规则判断，可复现但不完全自动化。
- 题集规模有限，更适合做版本对比，而非绝对能力排名。

## 7. 技术栈

Python · 多模型 API 调用 · 结构化 JSON 校验 · 固定随机种子 · 结果落库与可视化
