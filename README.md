# MingLi-Bench · 命理鉴心输出协议评测（证据索引版）

本仓库记录 [命理鉴心](https://minglijinxin.com)（紫微斗数 AI 分析产品）在**模型与提示词选型**上做过的对比工作，以及每条结论对应的证据位置。

> **当前状态（2026-11-24）**：这是一份证据索引，不是可复现的基准测试。早期对比是网页版手工完成的，题集、评分卡和打分表都没有存档。可复现的版本见第 5 节的计划，尚未开始。

## 1. 做过什么

| 项 | 内容 | 证据 | 可核验程度 |
|---|---|---|---|
| 单盘多模型对照 | 2026-05，同一张紫微命盘、同一段提示词，分别交给 8 个模型（Claude、DeepSeek、豆包、Gemini、GPT、Grok、Kimi、通义千问）生成报告，人工对比 | 8 份报告原文（PDF 和纯文本）及汇总笔记，存于作者本地，未公开 | 原文在，**没有打分** |
| 输出协议设计 | 规定报告末尾必须输出两个 JSON 标记：`SCORES`（6 维人格分，1–5 分，每一档锚定到星曜和宫位）、`CARD`（从 24 个三国人物里映射出的人格卡） | 私有仓库 `mingli-algo-core`：`prompts/shared.js` | 代码在 |
| 格式合规兜底 | 线上发现模型会漏输出、重复输出或输出残缺的 SCORES/CARD 标记，2026-09-30 重写解析器（v2）：宽松修复 JSON，≥4 维合法才采信，否则从正文抽取，缺失的维度补 3 分，保证最终各输出一个合法标记 | 私有仓库 `mingli-algo-core`：`lib/report-parser.js` | 代码在 |
| 线上模型 | DeepSeek API，默认 `deepseek-chat`，只设置了 `max_tokens`，**没有**固定 temperature 或 seed | `mingli-algo-core`：`config.js`、`lib/deepseek.js` | 代码在 |

私有仓库需要授权才能查看。

## 2. 结论（只保留有证据支撑的部分）

- **格式合规是线上的实际问题**：仅靠提示词约束，不能保证模型稳定输出结构化标记，必须在工程侧兜底解析。依据是 `report-parser.js` v2 的存在及其处理的几类失败情形。
- **线上选用 DeepSeek 的依据是成本和中文表现**，不是横评排名。横评只用来确认它可用。

## 3. 撤回的说法

本 README 的早期版本（2026-11-19）包含以下内容，现已撤回：

| 原说法 | 撤回原因 |
|---|---|
| `CARD + SCORES` 方案横评得分 45%，排名第 3 | 项目笔记里有这条结论的记录，但原始打分表和评分卡都没有存档，**无法复算** |

| Python、多模型 API、固定随机种子、结果落库 | 实际全部是网页版手工导出，没有 API 批量调用，也没有固定种子 |

## 4. 局限

- 单盘、单次、网页版：模型版本不可锁定，结果不可复现。
- 没有量化分数，只能做定性对比。

## 5. 可复现版本的计划（未开始）

1. 构造脱敏命盘题集，以文墨天机的排盘结果作为字段级标准答案。
2. 先定好评分卡（格式合规硬门槛、字段正确性、多次请求的一致性），**在看到任何结果之前**提交到仓库。
3. 通过 API 调用模型，固定参数，每题重复多次，原始输出全部落盘。
4. 打分脚本和原始结果一起公开，任何人都能复算。
