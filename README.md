# MingLi-Bench · 紫微斗数人格画像的确定性引擎与规则评测

[命理鉴心](https://minglijinxin.com) 的报告原本由 LLM 一次性完成两件事：**算**（六维人格分、24 个三国人物里匹配哪一个）和**说**（解读正文）。结果是同一张盘多次生成，分数和人物会不一致，输出的 JSON 标记经常缺失或残缺，只能在工程侧兜底，缺失的分数直接补 3。

本仓库把「算」的部分从 LLM 中拿出来，做成确定性代码，LLM 只负责解释算好的事实：

```
命盘（iztro 排盘）──► 确定性引擎（本仓库）──► 事实 JSON（分数 + 人物 + 每条依据）──► LLM 只写解读
```

```bash
npm ci
npm test            # 24 个测试
npm run simulate    # 在 21,600 张命盘上评测规则表，约 10 分钟，输出到 results/
```

需要 Node.js ≥ 22.18（直接运行 TypeScript，无构建步骤）。

## 用法

```ts
import { chartBySolar, computeProfile } from './src/index.ts';

const r = computeProfile(chartBySolar('2000-8-16', 2, '女')); // 时辰序号 2 = 寅时
r.scores;       // { 自我觉察: 3, 情绪调节: 4, 延迟满足: 3, 关系模式: 3, 不确定性容忍: 1, 自我叙事: 3 }
r.scoreDetail;  // 每个维度、每个宫位的加减分依据，例如「铃星坐宫」「太阴庙 + 太阴化科」
r.persona;      // { name: '徐庶·孝义', fullMatch: false, matched: [...], unmatched: ['命宫三方四正见文昌'], runnersUp: [...] }
```

## 结构

| 路径 | 内容 |
|---|---|
| `src/scores.ts` | 六维分：原提示词 `SCORES_RUBRIC` 的确定性实现 |
| `src/persona.ts` | 24 人物：原提示词 `PERSONA_MAPPING` 逐条改写的可执行条件 |
| `src/normalize.ts` | iztro 排盘结果 → 引擎内部结构（与排盘库解耦，测试可以手写命盘） |
| `test/` | 单元测试（手写命盘）+ 集成测试（iztro 真实排盘）+ 一条数学性质的测试 |
| `scripts/simulate.ts` | 分布评测脚本 |
| `docs/RULES.md` | 原文歧义的逐条解读与取舍 |
| `results/` | 评测输出（可复算） |

## 评测发现

把规则改写成代码后，在 21,600 张命盘上跑了一遍，发现**原规则表本身有问题**。这些问题在交给 LLM 处理时看不出来，因为模型会自行发挥、把空缺填上。详见 [`results/SIMULATION.md`](results/SIMULATION.md) 和 [`docs/RULES.md`](docs/RULES.md) 第三节。

1. **「刘备」这条规则在任何命盘上都不可能完全满足**。紫微与太阴、天同的位置差恒为奇数，而三方四正内的位置差只能是偶数。已写成测试。
2. **如果把「X+Y」按同宫解读，有 5 条规则不可能成立**（赵云、刘备、贾诩、孙策、鲁肃），因为这些星曜组合在安星规则下永远不会同宫。
3. **只有 32.89% 的命盘能完全匹配某个人物**，其余用户拿到的都是部分匹配。原提示词要求模型「严格对照映射、不可自行发挥」，但对三分之二的用户来说做不到。
4. **按原锚点打分，六维分整体偏低**：5 分在各维度只占 0%–2.6%，「关系模式」「自我叙事」在样本中从未出现 5 分。

## 局限与待办

- **排盘正确性依赖 iztro 2.5.8**。集成测试的期望值是对照 iztro 的宫位数据人工核对的，**还没有对照文墨天机**。下一步：补齐文墨天机导出的对照用例。
- `docs/RULES.md` 中的解读是设计决定，有讨论空间；评测发现第 3、4 条的具体数字会随解读而变，第 1、2 条不会。
- 尚未接入产品：引擎的输出要替换掉提示词里的 `SCORES_RUBRIC` 和 `PERSONA_MAPPING`，改为把事实 JSON 作为输入交给 LLM。
- LLM 层的评测（同一张盘多次生成时，正文是否忠实引用事实 JSON，幻觉率是多少）尚未开始。

## 关于早期版本

本仓库最初（2026-11-19）只有一份 README，其中写了「CARD+SCORES 方案横评 45%、排名第 3」、固定题集、5 组回归用例、固定随机种子等内容。实际情况是：当时只是在网页版上把 1 张命盘分别交给 8 个模型生成报告，然后人工对比；题集、评分卡和打分表都没有存档，**这些说法无法复算，已全部撤回**。当前仓库里的每个数字，都可以用 `npm test` 和 `npm run simulate` 复现。
